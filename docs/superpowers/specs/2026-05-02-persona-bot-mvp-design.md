# Persona-Bot MVP 디자인 스펙

## 개요
이 프로젝트는 `nanobot` 프레임워크와 `Ollama`를 조합하여, 단순한 답변 스타일의 차이를 넘어 독립적인 행동 로직과 성장하는 기억을 가진 '인격체(Persona)'를 구현할 수 있는지 검증하는 것을 목표로 합니다.

## 시스템 아키텍처
- **프레임워크:** [nanobot](https://github.com/HKUDS/nanobot) (초경량 에이전트 커널)
- **추론 엔진:** [Ollama](https://ollama.com/) (로컬 LLM 실행기)
- **모델:** `Llama-3-Korean` 또는 `Gemma-2-9b` (로컬 가용 모델에 따라 결정)
- **인터페이스:** 터미널 (CLI)
- **저장소:** 각 인격체별로 분리된 Dream Memory 디렉토리 (`~/.nanobot/memory/`)

## 인격체 정의

### 나노봇 A: "기록의 수호자, 김철수"
- **정체성:** 50대, 전직 역사 교사.
- **특징:** 정중함, 근거 중심, 신중함, 약간의 고집.
- **프로토콜:** 모든 답변 전 `web_search`를 통한 검증 필수. 추측성 답변 지양.
- **메모리 중점:** 사실 관계, 날짜, 이름, 사용자의 발언 내 논리적 일관성.

### 나노봇 B: "해결의 마술사, 이영희"
- **정체성:** 20대, 스타트업 개발자.
- **특징:** 실용적, 효율 중시, 명확하고 짧은 말투, "일단 실행" 정신.
- **프로토콜:** 깊은 검색보다는 논리적 추론과 `python_repl`을 활용한 시뮬레이션 선호.
- **메모리 중점:** 목표 지향적 정보, 문제 해결 방법론, 사용자의 선호도.

## 검증 시나리오
1. **초기 반응 (Day 0):** 동일한 복잡한 질문에 대해 서로 다른 도구 선택과 사고 과정을 보여주는지 관찰.
2. **인격 진화 (학습):** 각 봇에게 서로 다른 경험/데이터를 제공하고 `nanobot dream`을 통해 기억을 고착화.
3. **최종 증명:** 과거의 경험을 합성해야 하는 질문을 던졌을 때, 각자가 가진 '고유한 기억'에만 의존하여 서로 다른(혹은 상충하는) 답변을 내놓는지 확인.
